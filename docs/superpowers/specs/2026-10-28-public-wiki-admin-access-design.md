# Wiki / 知识图谱公开访问与管理员权限设计草案

日期：2026-10-28
基于：main / b918b39
状态：建议方案，待用户审阅；尚未实施产品代码。

## 1. 目标与建议默认值

访客免登录浏览公开 Wiki 与知识图谱；管理员登录后使用原有工作台、知识库管理、AI runtime、编辑、导入、发布、渠道、账号及设置等功能。

以下是本方案的建议，尚不代表用户已确认：

- 单站点、单管理员账号；访客无需注册。
- 每个知识库单独开启公开访问，默认关闭；不自动公开任何已有知识库。
- 开启后，公开范围中的文件修改会实时反映到网站；初版不设草稿、审核及发布版本。
- 默认公开 `wiki/` 内 Markdown 正文及明确允许的图片；不公开整个知识库根目录。
- 公开展示包含目录、正文、站内搜索、双向链接、全局图谱和局部图谱。
- 访客不能 AI 问答或触发任何 Agent 任务；图谱缺失节点也不能触发创建文件。
- 本地桌面使用与服务器访问采用显式模式；公网服务器必须开启权限控制。

如果“公开全部知识库”或“修改后先审核再发布”是实际需求，需要在实施前调整上述默认值。

## 3. 方案比较

| 方案 | 做法 | 取舍 |
| --- | --- | --- |
| A：同项目增加公开只读区（推荐初版） | 沿用 React、Hono、SQLite；新建公开读取 API，原 API 统一管理员鉴权 | 改造范围可控，修改实时可见；必须统一过滤正文、图谱、搜索、资源及缓存 |
| B：独立发布快照 | 管理员把选定内容导出为静态网站或只读快照，再单独部署 | 发布内容与工作区隔离，可做版本；增加构建、发布、撤回和同步机制 |
| C：另建独立公共服务 | 公共服务只接收同步后的公开数据，管理服务单独运行 | 部署隔离更强；同步和运维工作更大，当前阶段收益有限 |

建议先完成 A。如果需要审核发布、SEO 服务端渲染、大规模 CDN 或独立站点，再增加 B；初版不预先搭建这些机制。

## 4. 页面与权限

建议服务器端路由：

- `/`：公开知识库列表，没有公开内容时展示空状态。
- `/wiki/:slug`：公开 Wiki 目录与首页；正文路径通过 `?file=wiki/...md` 表示，刷新可恢复。
- `/graph/:slug`：公开图谱；点击节点跳到对应公开正文。
- `/admin/login`：管理员登录。
- `/admin/*`：管理员工作区，保留现有功能并统一路由前缀。

| 能力 | 访客 | 管理员 |
| --- | --- | --- |
| 已公开 Wiki / 图谱 / 搜索 / 允许的图片 | 只读 | 可读 |
| 未公开知识库和根目录原始材料 | 无权访问 | 可读写 |
| Wiki 构建、导入、编辑、删除、重新命名 | 无权操作 | 可操作 |
| AI 对话、任务、工具结果、会话记录及 SSE | 无权访问 | 可操作 |
| 运行时、API Key、技能、渠道、维护和关机 | 无权访问 | 可操作 |
| 云端账号、资源市场、发布和购买信息 | 无权访问 | 可操作 |
| 公开开关、站点名称、公开范围 | 无权操作 | 可设置 |

服务器模式采用后端白名单：只开放指定的公开 GET/HEAD 接口、站点入口、登录流程及最小健康检查；其余 `/api/*` 默认要求管理员。不能按“所有 GET 都公开”判断权限。

未登录调用管理 API 返回 401；无有效 CSRF 凭证的写请求返回 403；公开区访问未公开知识库、越界文件或不存在资源统一返回 404。公开响应不含本机路径、运行配置、凭据、内部日志或私有文件计数。

## 5. 管理员登录与部署模式

### 独立管理会话

- 管理员身份独立于现有 Molio 云账号；原 `/api/auth/*` 仍属于后台功能。
- 初版管理员名由部署配置提供，密码仅保存 scrypt 哈希。提供交互式脚本生成哈希，通过终端隐藏输入密码，避免把明文放入命令参数。
- 登录成功生成随机会话 token；浏览器持有 HttpOnly Cookie，SQLite 仅保存 token 摘要及到期时间。
- 会话绝对有效期建议 12 小时；退出、修改管理员凭据或运维重置后撤销会话。多浏览器会话各自独立。
- 公网 HTTPS Cookie 使用 Secure、SameSite=Lax；管理写请求同时校验 CSRF token 与配置的站点 Origin。不依赖任意 Host 头推断可信来源。
- 登录加失败限速；认证接口及管理响应使用 `Cache-Control: no-store`。
- 已建立的管理 SSE 在会话失效或到期后关闭；退出时客户端中止管理请求、清空私有缓存并跳转登录页。

### 模式及配置（建议命名）

| 配置 | 用途 |
| --- | --- |
| `MOLIO_ACCESS_MODE=local\|server` | local 为桌面/本机开发；server 为公开服务 |
| `MOLIO_PUBLIC_URL` | server 必填，规范化的 HTTPS 站点地址，也是可信 Origin |
| `MOLIO_ADMIN_USERNAME` | server 管理员名 |
| `MOLIO_ADMIN_PASSWORD_HASH` | server 必填，带参数的 scrypt 编码结果 |
| `MOLIO_HOST` | local 仅允许回环地址；server 可监听容器内 `0.0.0.0` |

local 模式维持本机免登录操作，但只绑定回环地址；明确禁止通过该模式开放远程访问。server 缺少必要配置时启动失败并提示，不自动降级为免登录。Docker/安装脚本显式使用 server 模式；Electron 显式使用 local 模式。HTTPS 由反向代理终止，首次管理访问也使用 HTTPS。

## 6. 公开内容的统一范围

新增独立的公开设置记录，按 vault 保存 `enabled`、稳定且唯一的 `slug`、`title`、`description`、`policyVersion`、`updatedAt`。已有 vault 迁移后均不公开。

初版范围以固定规则实现，避免立即引入逐文件 ACL 编辑器：

1. 公开 `wiki/**/*.md`，包含首页 `wiki/INDEX.md`；排除 `LOG.md`、隐藏目录、配置文件。
2. 默认仅允许 `wiki/assets/` 内 PNG/JPEG/WebP/GIF 等图片；其他目录的附件先在后台迁移或另行明确允许。首版不开放任意文件下载，也不直接托管原始 HTML/SVG。
3. 公开服务对相对路径统一规范化，并通过真实路径确认仍在允许目录内；拒绝路径穿越、反斜杠绕过、符号链接越界及编码绕过。
4. 双链解析只使用公开文档索引；不允许查询整个知识库再返回私有目标信息。
5. 公开图谱只由公开文档构建，节点、边、统计和缺失链接均不得带出私有文件信息。未解析目标不生成公开死链节点。
6. 搜索先限定公开文档集合，再计算命中、摘要、数量和分页；不能搜索整库后只过滤结果列表。
7. Markdown 正文使用严格 HTML 清理；链接和图片重写到公开接口，内部私有路径不生成可访问链接。正文里管理员主动写入的文字本身视为公开内容，需要管理员确认适合发布。
8. 访客所选知识库和正文由 URL/浏览器保存，不写入 daemon 的全局 `active-vault`。

目录、正文、搜索、双链、图谱与图片统一依赖同一个 `PublicContentService`，不在各路由重复实现范围判定。

## 7. API 边界

建议新增接口，具体命名在实施时按以下契约保持一致：

| 接口 | 权限 / 行为 |
| --- | --- |
| `GET /api/access/session` | 返回 local/server、管理员是否登录和必要的 CSRF 信息；不返回云账号或系统配置 |
| `POST /api/access/login` | 登录并设置管理 Cookie |
| `POST /api/access/logout` | 撤销当前管理会话 |
| `GET /api/public/vaults` | 仅返回公开库的 slug、名称、简介 |
| `GET /api/public/vaults/:slug/tree` | 公开目录 |
| `GET /api/public/vaults/:slug/file?path=...` | 公开 Markdown 正文 |
| `GET /api/public/vaults/:slug/resolve?target=...` | 仅解析公开双链 |
| `GET /api/public/vaults/:slug/graph` | 公开图谱；可带公开 file/dir scope |
| `GET /api/public/vaults/:slug/search?q=...` | 公开全文搜索；限制查询长度、结果数及请求频率 |
| `GET /api/public/vaults/:slug/assets/*` | 仅提供范围内允许的图片 |
| `GET/PUT /api/admin/publication/:vaultId` | 管理员读取/保存公开设置，记录设置历史 |

保留原有管理 API 地址，在 server 模式统一加管理员鉴权，减少对 CLI、桌面和业务模块的侵入。远程 CLI/MCP 初版不增加管理员自动化凭证；本地模式继续工作。

公共读取初版使用 `no-store`；服务内缓存按 vault、内容版本、policyVersion 分区。撤销公开、删除文件、改 slug 后立即使相关缓存失效，并在每次公开请求入口重查开关。已被访客下载或保存的内容无法收回。

公开响应的新鲜度不能只依赖 watcher 事件。初版每次请求都重新确认当前公开文档集合及真实路径，结合文件大小/修改时间等签名判断缓存是否可复用；正文与图片在读取时再校验目标，树、搜索和图谱只使用本次确认的集合。watcher 未就绪、失效或漏事件时仍必须执行这些检查，无法确认就重算或拒绝返回；不能返回旧的私有节点、已删除正文或旧搜索摘要。验收以新请求执行范围校验时的文件状态为准，不承诺收回此前已发送的内容。后续优化必须保留该边界。

## 8. 前端复用边界

- 顶层只初始化主题、语言及最小访问状态，再选择 PublicApp 或 AdminApp。
- 公开区单独使用 `publicClient`；不调用原配置、会话、账号、运行时及全局活动库 API。
- Markdown 复用渲染器的严格模式；公开正文的链接行为独立适配。
- 图谱提取不发业务请求、不写文件的展示组件，由 PublicGraphPage / 原 GraphPage 各自供数。后台继续保留原有交互，公开视图仅浏览。
- server 模式管理页迁入 `/admin/*`；原 `/knowledge`、`/chat`、`/settings` 等旧地址按模式重定向到受保护位置。Electron 协议和历史路由保持可用。
- 浏览器端路由守卫用于页面体验；最终权限由后端判断，直接请求 URL/API 同样受控。

## 9. 实施顺序与验收

1. 后端访问控制与管理员登录先落地：未登录不能访问现有管理 API。
2. 公开设置、统一内容范围与公开 API：用包含公开/私有文档、附件及交叉链接的夹具证明过滤一致。
3. 公开 Wiki 和图谱页面：直接访问、刷新、搜索、双链跳转可用，访客不产生管理请求。
4. 管理设置页与路由整合：管理员开启/撤销公开，多个浏览器互不影响。
5. 部署与回归：HTTPS、重启、登录过期、桌面 local 模式、Docker server 模式均能正常工作。

必须验收：匿名可读公开内容；匿名无法访问任何管理能力；私有文件及信息不从树/图谱/搜索/资源中泄露；关闭公开立即停止新请求；Cookie/CSRF/过期/退出有效；管理员保留原有工作流。

## 10. 初版边界与后续选择

初版不包含多级角色、普通注册用户、公开 AI 问答、逐文件审核、静态快照发布、全文站点 SSR/SEO 和远程管理 API token。后续按真实需求单独增加。

实施前最影响范围的选择是：是否接受“指定知识库的 wiki 目录开启公开后，编辑即实时对外可见”。本草案按接受该行为估算和分解任务。
