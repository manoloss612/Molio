## 1. 目标与事实

用户希望 Wiki 和知识图谱可以公开访问，其他管理功能只对管理员开放。本阶段要让未登录访客浏览已发布的 Wiki 页面和基于这些页面生成的图谱；管理员负责选择、预览、发布、更新和撤回。

现状：server 模式在 `apps/daemon/src/core/access/guard.ts` 对管理 API 默认鉴权；`apps/web/src/access/AccessBoundary.tsx` 将业务 App 整体置于管理员入口后。`apps/daemon/src/routes/graph.ts` 扫描知识库内所有 Markdown，现有图谱数据还包含路径和死链信息。因此公开访问需要单独的只读边界，以及只由可公开内容构建的图谱。现有市场发布接口 `apps/daemon/src/routes/publish.ts` 用于其他发布链路，不能直接视为公开 Wiki 的权限模型。

二期已有管理员认证和真实 HTTPS 测试夹具，但未验证生产反向代理和真实证书。本期实施从二期代码继续，实际发布前仍需完成独立环境及生产部署验收。

## 2. 关键产品选择与建议

**用户已确定：**公开内容为 Wiki 和图谱；管理员逐篇选择哪些 Wiki 页面公开；访客读取已发布快照，源文件变化仅在管理员再次预览并发布后生效；其他管理能力保持管理员访问。

**本设计建议（供用户审阅）：**

1. 默认私有；访客读取不可变发布快照。源文件的新增、修改或删除不自动改变当前公开版本，管理员再次预览并发布后更新。（用户已确认此语义。）
2. 首期一个公开站点绑定一个 vault；候选页面来自该 vault 的 `wiki/` 下 Markdown。切换站点 vault 前管理员须确认关闭并清空当前公开站点。
3. 发布预览列出页面、正文、Wiki 链接解析结果及引用图片。只允许经预览确认的 PNG/JPEG/GIF/WebP 本地图片进入快照；SVG、HTML、脚本、远程图片及其他附件不发布。保留原图，不承诺清除图片元数据，并在预览明确提醒管理员检查。
4. 默认关闭公开站点。发布内容不自动启用站点；管理员另行启用。撤回或关闭后，新请求不再获得相应页面、图谱节点和未被其他已发布页面引用的图片。
5. 首期不含公开全文搜索、评论、访客编辑、公开 AI、多 vault、多站点和其他附件类型。正文内普通文本、图像内容及个人信息不能由系统可靠判断；发布预览明确告知管理员自行审阅。图片元数据不自动清除，预览提示管理员自行检查。

管理员需要审核所有将公开的正文和图片。系统会阻止私有路径、未发布文档和不安全资源通过结构化接口泄露，但不能自动判断正文中写出的名字、事实或图片内容是否敏感；预览需明确提示这一点。

## 3. 备选方案

| 方案 | 行为 | 取舍 |
|---|---|---|
| A. 逐篇选择 + 发布快照（用户已确认） | 管理员明确选择文档；每次发布固定正文、所需资源和图谱版本 | 发布范围和撤回可解释；需要保存快照及处理一致性 |
| B. 逐篇选择 + 实时读取原文件 | 管理员选择后，访客始终看到当前本地文件 | 数据复制较少；未审阅的后续改动立即公开，撤回和并发读取更难保证 |
| C. 整库公开 + 快照 | 管理员一次公开整库，发布后看到该批快照 | 操作简单；容易将不打算共享的文档和关联信息一起公开 |

A/B/C 均须保持管理 API 的认证边界。用户选择 A 的逐篇范围；本设计推荐 A 的快照语义，因为它使“确认发布的内容”与访客实际可读内容一致。

## 4. 建议的使用流程

1. 管理员在受保护的知识库界面进入“公开发布”，选择一个 vault 内要公开的 Wiki Markdown 页面。
2. 系统给出拟公开页面、正文预览、图片清单及无法安全处理的链接/资源；管理员确认完整发布范围。默认未选择的页面为私有。
3. 预览创建不可变候选，发布确认只接受当前管理员会话内、尚未过期的该候选。源文件在预览后改变也不能悄悄替换已确认内容；过期、重启或预览丢失时要求重新预览。若活动版本已被其他操作替换，则报告冲突并重新预览。点击发布后建立新的完整公开版本；失败保留旧版本并提示原因。
4. 管理员可重新发布选中的页面、撤回单页、关闭整个公开站点。页面撤回后图谱同步移除对应节点及相连边，资源仅在仍被其他已发布页面引用时保留。
5. 访客通过公开入口访问页面列表、Wiki 正文和只读图谱，点击图谱节点进入相应公开页面。登录入口进入原管理员流程；访客看不到编辑、聊天、配置或知识库管理入口。

发布选择与站点开关持久化。默认没有公开版本且站点关闭；发布快照不会自动开启站点，管理员须单独启用；并发发布不得撤销关闭操作。重启后恢复最后一次已提交的发布状态。已发布内容来自独立快照，删除或改写源文件不会自动改变公开版本；需要更新或撤回时由管理员明确操作。公开内容被第三方保存后无法召回，撤回只控制随后向本站发出的请求。

## 5. 数据、接口与访问边界（草案）

- **首期容量上限（实施值）：**每个活动 revision 最多 1,000 篇页面、20,000 条图谱边；单篇 Markdown UTF-8 大小不超过 512 KiB、单页最多 50 个不同图片资源；单张图片不超过 8 MiB；整批 Markdown 与图片原始字节合计不超过 48 MiB。管理员同一时间最多持有一个预览候选，10 分钟后过期，daemon 重启时清空。超过上限时预览失败并指出具体限制，不截断后悄悄发布。以上限制是本期实现约束，不代表产品永久上限。
- **容量依据：**在临时 SQLite 中用合成数据插入 1,000 篇各约 39,698 字节 Markdown 和 1 张 8 MiB 图片（共 48,086,608 字节），事务耗时 576 ms，主数据库 49,397,760 字节、WAL 49,711,952 字节、RSS 增量 18,587,648 字节。另以较大的合成负载（256 篇各约 216,018 字节 Markdown 和 6 张各 10 MiB 图片，共 118,215,168 字节）压测，事务耗时 1,442 ms，主数据库 118,583,296 字节、WAL 119,302,872 字节、RSS 增量 82,014,208 字节。20,000 条图谱边 JSON 为 675,601 字节、RSS 增量 7,094,272 字节。测试证明所选上限可在合成环境下完成事务且峰值可界定；单预览候选避免叠加内存占用。未读取用户 vault 内容。
- 快照是发布时复制的公开投影，不保存文件系统绝对路径、vault ID、内部文件路径、私有目录结构或额外 frontmatter。每篇文档使用不透露本地路径的稳定随机公开 ID；允许公开的标题和正文由管理员预览确认。
- 批次持久化建议复用现有 SQLite：版本、页面、经批准的图片及公开图谱在事务中写入并切换活动版本。提交前任一步失败均不改变活动版本；发布、撤回和关闭操作串行化。上限按本节首两条执行。
- 图谱从活动版本里的公开页面和公开链接构建，只包含公开页面节点、两端均公开的边及展示所需字段。不能暴露当前 `GraphData.path`、`deadLinks`、私有标题、源 vault 或对私有节点的统计。节点只指向有效的公开页面。
- 内部可保留每篇已批准页面的原始内容快照以重新解析链接，但匿名 API 只提供净化后的公开投影。其他页面加入或移出公开集合时，原正文快照不变，链接可点击状态和图谱可随新集合重算；管理员预览需显示此影响。
- Wiki 链接先按已发布集合解析；目标不公开、歧义或不存在时显示中性不可点击提示，禁止输出目标私有路径或私有标题到链接属性。普通正文中管理员主动写入的文本不视为自动脱敏；预览必须保留告知。
- 仅允许预览中确认的本地 PNG/JPEG/GIF/WebP 图片进入快照；检查真实路径、符号链接、文件签名、大小和类型，设置 `X-Content-Type-Options: nosniff`。SVG、HTML、脚本、远程图片及其他附件默认不发布；图片原始元数据保留，发布预览须提示图片可能含个人信息，管理员自行检查。
- 公开 Markdown 的 frontmatter 使用明确的字段白名单；原始 HTML、危险 URL 协议和脚本不得执行。优先复用现有 `MdRenderer` 的不可信内容净化能力，但必须通过公开场景的恶意内容测试证明，并禁止未经批准的远程图片或指向管理 API 的资源加载。完整 Markdown 格式支持范围需在预览说明。
- 拟采用独立只读接口：`GET/HEAD /api/public/site`、`/api/public/pages/:pageId`、`/api/public/graph`、`/api/public/assets/:assetId`。ID 使用限定字符和长度，其他方法、未知路径、编码歧义与异常斜杠仍走管理员门禁。管理员的选择、预览、发布、撤回、开关为独立受保护写接口，沿用 Origin/CSRF 和现有会话规则；不复用匿名管理 API。
- 匿名 API 只返回当前活动快照；站点关闭、页面不存在、已撤回或 ID 无效时返回统一的不可用响应，不以不同错误泄露私有对象是否存在。响应及附件使用 `Cache-Control: no-store`；代理验收必须确认不会覆盖该策略。已开始的下载、第三方缓存和访客已保存的副本不能保证召回。
- 公开站点接口返回活动 `revision`。页面、图谱和图片请求携带该版本；如果版本已切换，则统一返回版本已更新的响应，访客重新加载站点并读取最新版本；不得通过旧版本参数读取已撤回内容。服务端在同一读事务中检查活动版本并取得响应数据。跨多个请求时客户端不得把不同版本的数据合并显示。
- 预览候选绑定管理员会话、设定容量与有效期，限制同时存在的候选数量；候选不能通过匿名接口读取，过期、退出或取消后清理。清理无引用旧快照，数据库 WAL、备份和已被访客保存的副本仍可能保留历史数据；不承诺安全擦除。
- 公共入口采用单独只读 shell 和明确路由（例如 `/public/wiki`、`/public/wiki/:pageId`、`/public/graph`），在管理员 `AccessBoundary` 外加载；其余路径保持现有权限流程。公开页面不得依赖管理 App、`/api/knowledge/*` 或 `/api/graph/*` 来获取内容。直接深链与刷新应工作。

接口名称、存储结构和路由是实现建议，需结合下一步评审确认后固定；不能仅凭客户端过滤或隐藏按钮构成权限边界。

## 6. 可验证的完成条件

1. 匿名访客能打开已发布的页面列表、Wiki 页面和图谱并在二者间导航；直接深链、刷新、移动窄屏可用。
2. 不通过公开 API、页面的结构化元数据、链接、图谱节点/边、资源或错误暴露未发布文档的标题和路径；指向未发布文档的链接转换为中性提示。管理员明确放进公开正文的普通文本仍会公开，需要在预览时自行审阅。攻击性路径、方法变体及编码变体不能触达管理接口。
3. 预览后源文件改变时，发布的内容仍与已确认候选一致或要求重新预览；绝不悄悄发布新内容。页面和所需图片、图谱来自一致的已提交版本。源文件变化不改变公开版本；再次发布才更新。模拟发布失败、并发发布及访客读取时版本切换，访客只看到前一个或下一个完整版本。
4. 单页撤回后，新的页面/图谱/资源请求均符合最新发布集合；共享图片仍被其他公开页面使用时可访问；关闭站点后匿名入口不可访问，重启后状态保持。
5. 管理员必须经过现有会话和 CSRF 才能预览私有内容或更改发布状态；匿名访问管理 API、写接口、源 vault、云账户和聊天仍被拒绝。
6. 恶意 Markdown、链接、资源类型和路径穿越不会执行脚本、加载未批准资源或越出 vault；大文件、缺失资源和不支持格式有清楚的失败/提示行为。
7. 全部公开链路通过真实浏览器的隔离 server HTTPS 验收；本机 local、桌面兼容、现有管理 API 和受影响的 Web 全量回归通过。只对实际执行的部署和平台作结论。

## 7. 实施前置与边界

一期 PR #1、二期 PR #2 仍是有依赖关系的 Draft PR；实施分支以二期已验证 HEAD 为基线，并在集成前重新核对 PR 冲突、目标分支、review 和 CI。生产环境需要真实 HTTPS、反向代理不缓存公开响应、备份恢复和回滚验证；本规划不授权合并 PR 或对公网部署。

本期只规划本地单管理员、单 daemon 场景；多管理员、复杂授权、自动定时发布、公开搜索、评论和其他附件另立设计。公开范围和快照语义已由用户选定；站点绑定、允许的图片类型及原图元数据提示、预览交互是本设计给出的默认建议，待用户审阅后再实施。
